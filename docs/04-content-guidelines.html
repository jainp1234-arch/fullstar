1Rules for Claude Code

  1. Use only the tokens in section 17. No hard-coded colours, sizes, radii, shadows or durations in components.
  2. Build only the components in section 11. If a screen needs something that is not listed, stop and ask.
  3. Every screen uses one of the shells in section 10.
  4. Every piece of text follows sections 15–16. Use the exact strings given; put all strings in one English strings file (no text inside templates).
  5. One fixed look: no dark mode. Do not read prefers-color-scheme.
  6. Do not copy the name, logo, characters or artwork of any other app. Only the assets listed in section 9 may be used.

2The look

A night-sky header (deep purple gradient with small stars) sits on top of every screen. Content lives on white rounded cards with a thick solid bottom edge that makes them feel pressable, like toy blocks. Headings are indigo, accents are cyan, pink and gold. The tone is calm and friendly, never noisy.

14Accessibility

  • Target: WCAG 2.1 AA. Only the colour pairs listed in section 3.
  • Never use colour alone: status chips always have an icon and text; correct answers have a check icon.
  • Every image has alt text from the strings file; decorative stars and edges are aria-hidden.
  • Every kid-mode screen has app-read-aloud; it reads the screen title and instructions using the narrator voice.
  • Logical focus order, visible focus ring, all actions reachable by keyboard; dialogs trap focus and return it on close.
  • Screen-reader live region announces stars earned, upload status changes and toasts.
  • lang="hi" on every Hindi text element so screen readers pronounce it correctly.

18Angular implementation

  • Shared library: libs/ui/ holds the tokens, fonts, icons, illustrations and every app-* component. Both apps import from it; no app defines its own visual components.
  • Mode switch: the root element gets data-mode="kid" | "parent" | "studio"; the type scale follows automatically.
  • Angular Material 22: used only for behaviour-heavy parts (dialog, bottom sheet, menu, table, snack bar, form-field logic). Map its system tokens to ours in styles.css: --mat-sys-primary: var(--color-primary-600), --mat-sys-on-primary: #FFFFFF, --mat-sys-surface: var(--color-surface), --mat-sys-on-surface: var(--color-text), --mat-sys-outline: var(--color-border), --mat-sys-error: var(--color-error-700), --mat-sys-corner-medium: var(--radius-md), --mat-sys-corner-large: var(--radius-xl), --mat-sys-body-large: var(--type-body), --mat-sys-label-large: var(--type-label). Do not use Material buttons, cards or chips; use ours.
  • Fonts and icons: files in libs/ui/assets/fonts/; declared with @font-face; precached by the service worker so they work offline.
  • Sky star layer: one shared SVG (libs/ui/assets/sky-stars.svg, 40 circles at fixed positions) used as a background image on every sky header.
  • Strings: libs/ui/strings/en.ts, typed constant object; components read text only from there.
  • Verification: a Storybook-free "UI gallery" route (/dev/ui, dev builds only) shows every component in every state, used for review.

Assets to add to the Tech Stack document (vendored files, not npm packages): Poppins font files (google/fonts, OFL), Material Symbols Rounded variable font (google/material-design-icons, Apache-2.0, 50k+ stars), Fluent Emoji 3D PNGs (microsoft/fluentui-emoji, MIT, ~9k stars — exception: official Microsoft set, no comparable free 3D set).
