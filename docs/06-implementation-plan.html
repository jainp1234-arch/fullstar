1How to run each step

  1. Start: open a new Claude Code session in the repository and say: Do step <ID> of docs/06-implementation-plan.html.
  2. Claude Code reads CLAUDE.md, the step, and the document sections listed under it. It creates branch step/<id>-<short-name> from an up-to-date main.
  3. It builds only what the step lists. Anything unclear or missing from the documents: stop and ask; never invent a design, table, endpoint or dependency.
  4. Done when (every step, in addition to its own checks):
    • All tests pass locally and in CI; lint and format clean.
    • New behaviour has tests (backend service coverage stays at or above 80%).
    • /security-review run on the branch; findings fixed or listed in the PR.
    • The feature can be shown working (running app, UI gallery or test output).
    • Any document affected is updated in docs/ in the same PR.
  5. Finish: push, open a PR using the template (what changed, how to test, screenshots, document updates, open questions). Atul reviews, then squash-merges.
  6. Sizes: S about 2 hours, M about half a day, L a full day (split into a/b sessions if it runs over).

# FullStar – instructions for Claude Code

## Source of truth (read the sections a step names; never contradict them)

docs/05-backend-schema.html     Backend Schema     – SQL, RLS, auth flows, endpoints, jobs
docs/06-implementation-plan.html This plan         – do one step per session

## Always
- Exact versions only (no ^ ~ latest). Docker tags pinned. Multi-arch images (amd64 + arm64).
- API: /api/v1, envelope { status, data, error }, error codes from Schema §10.
- Java 21, Spring Boot 4.1.1, constructor injection, custom exceptions, Bean Validation,
  SLF4J structured logs (no personal data), Resilience4j on every outside call.
- SQS jobs: idempotency key, DLQ, max 3 receives. Only the API touches the database.
- Angular 22: standalone components, reactive forms, signals, OnPush, no `any`,
  UI only from libs/ui, text only from libs/ui/strings/en.ts.
- Never commit secrets; update .env.example with new variable names.
- Stop and ask if a document is silent or two documents disagree.

## Commands
make up / make down        start / stop local services (docker compose)
make test                  all tests          make lint      all linters
make api / make family / make studio          run one app locally
